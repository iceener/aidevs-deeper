  -H "Content-Type: application/json" \

  -d '{

## Streaming Overview

Stream Chat Completions in real time. Receive chunks of completions returned from the model using server-sent events.

## The Chat Completion Chunk Object

Represents a streamed chunk of a chat completion response returned by the model, based on the provided input.

### Top-Level Properties

-   **`id`** (`string`): A unique identifier for the chat completion. Each chunk has the same ID.
-   **`object`** (`string`): The object type, which is always `chat.completion.chunk`.
-   **`created`** (`integer`): The Unix timestamp (in seconds) of when the chat completion was created. Each chunk has the same timestamp.
-   **`model`** (`string`): The model that generated the completion.
-   **`system_fingerprint`** (`string`): This fingerprint represents the backend configuration that the model runs with. Can be used in conjunction with the `seed` request parameter to understand when backend changes have been made that might impact determinism.
-   **`choices`** (`array`): A list of chat completion choices. Can contain more than one element if `n` is greater than 1. Can also be empty for the last chunk if you set `stream_options: {"include_usage": true}`.
-   **`usage`** (`object` or `null`): Usage statistics for the completion request. (Appears in the final chunk if `stream_options: {"include_usage": true}` is set).

### `choices` Array Item Properties

Each item in the `choices` array has the following properties:

-   **`index`** (`integer`): The index of the choice in the list of choices.
-   **`delta`** (`object`): A chat completion delta generated by streamed model responses. See details below.
-   **`logprobs`** (`object` or `null`): Log probability information for the choice.
-   **`finish_reason`** (`string` or `null`): The reason the model stopped generating tokens. Possible values:
    -   `stop`: Model hit a natural stop point or a provided stop sequence.
    -   `length`: Maximum number of tokens specified in the request was reached.
    -   `content_filter`: Content was omitted due to a flag from content filters.
    -   `tool_calls`: Model called a tool.
    -   `function_call` (deprecated): Model called a function.

### `delta` Object Properties

The `delta` object contains the changes in this chunk:

-   **`role`** (`string`): The role of the author of this message (usually `assistant`). Typically present only in the first chunk.
-   **`content`** (`string` or `null`): The contents of the chunk message.
-   **`tool_calls`** (`array`): Details about tool calls made by the model. Each item contains:
    -   `index` (integer)
    -   `id` (string)
    -   `type` (string, always `function`)
    -   `function` (object):
        -   `name` (string): The name of the function called.
        -   `arguments` (string): The arguments to call the function with, accumulated across chunks.
-   **`function_call`** (`object`, **Deprecated**): Deprecated and replaced by `tool_calls`. Contains `name` and `arguments`.
-   **`refusal`** (`string` or `null`): The refusal message generated by the model, if any.

## Streaming API Responses

Learn how to stream model responses from the OpenAI API using server-sent events.

By default, when you make a request to the OpenAI API, the model's entire output is generated before sending it back in a single HTTP response. When generating long outputs, waiting for a response can take time. Streaming responses lets you start printing or processing the beginning of the model's output while it continues generating the full response.

### Enable Streaming

Streaming Chat Completions is fairly straightforward. Set `stream=True` when calling the Chat Completions endpoint. This returns an object that streams back the response as data-only server-sent events.

The response is sent back incrementally in chunks. You can iterate over the event stream.

### Example: Stream a Chat Completion (Python)

```python
from openai import OpenAI
client = OpenAI()

stream = client.chat.completions.create(
    model="gpt-4o",
    messages=[
        {
            "role": "user",
            "content": "Say 'double bubble bath' ten times fast.",
        },
    ],
    stream=True,
)

for chunk in stream:
    print(chunk)
    # Example accessing the delta content:
    # if chunk.choices:
    #    print(chunk.choices[0].delta)
    print("****************")
```

### Read the Responses

When you stream a chat completion, the response object for each chunk has a `delta` field instead of a `message` field. The `delta` field holds the incremental changes (e.g., a `role` token, `content` tokens, `tool_calls`, etc.).

### Example: Stream Only Text Content (Python)

To concatenate and print only the text content from the stream:

```python
from openai import OpenAI
client = OpenAI()

stream = client.chat.completions.create(
    model="gpt-4o",
    messages=[
        {
            "role": "user",
            "content": "Say 'double bubble bath' ten times fast.",
        },
    ],
    stream=True,
)

full_response = ""
for chunk in stream:
    if chunk.choices and chunk.choices[0].delta.content is not None:
        content = chunk.choices[0].delta.content
        print(content, end="")
        full_response += content

print("
--- Full Response ---")
print(full_response)
```

## Moderation Risk

Note that streaming the model's output in a production application makes it more difficult to moderate the content of the completions, as partial completions may be more difficult to evaluate. This may have implications for approved usage.
